# PDF 单文件交付（2026-11-16）

部分上游模板只返回一个 PDF。旧转发器强制要求 PDF 和图片同时存在，导致已付款、已生成 PDF 的订单反复重试并停留在等待交付。

经用户确认，新规则为：有 PDF 和图片则一起交付；只有 PDF 则交付原 PDF，邮件准确标明“PDF · 1 个文件”。不生成缺失图片，不修改上游文件内容。缺少可交付 PDF、只有图片、超出大小限制或仅含内联附件仍不会误报完成。

新建邮箱任务保存 `allowPdfOnly: true`。已有历史任务缺少此标记时保留原要求，避免升级后意外重放旧任务。当前已付款受影响订单在用户确认后单独启用了该标记；没有重新建单或付款。

邮件仍遵循现有交付防重状态：发送成功先保存 `sent`，之后完成 Telegram 和订单页回调才保存 `delivered`。回调重试不重发已保存为 sent 的邮件。

验证：42项机器人模块测试通过，其中新增4项覆盖单 PDF、PDF+图片、历史任务保持严格要求、缺 PDF/超限/内联附件拒绝，以及邮件描述与真实附件数量一致。Windows部署前执行新增测试通过；线上受影响任务已完成交付，已发送文件夹核对收件人及单个 PDF 附件正确，Telegram 和网站回调完成，订单数据库状态为 delivered，订单页返回 HTTP 200。没有修改第三方 API、付款钱包或付款记录。

备份：`config/restore-overlays.json` 在原验证码修复上追加转发器和测试文件，恢复原始加密快照时会一起校验并应用。邮箱重新授权保存的是新 DPAPI 凭据；旧快照中的授权可能过期，正式迁移前应做最新快照，必要时在新机重新授权原邮箱。
