# 浏览器连接修复（2026-11-17）

现场发现自动填表 Chrome 未运行，本机调试端口 9333 返回 ECONNREFUSED。普通 Chrome 进程仍存在，但没有使用自动化配置目录和调试端口，因此不能代替填表浏览器。网站、上游首页、Telegram 在检查时均可连接。计划任务结果为 0；现有记录不足以判断浏览器是被关闭还是因其他原因正常退出。

旧代码直接请求 `/json/list`，连接失败只显示 `fetch failed`。此外，WebSocket 断开时没有拒绝未完成的 CDP 请求，可能留下悬空的顶层 await 并以退出码 13 终止。

修复后的行为：

- 在访问表单之前检查调试端口。已正常运行的浏览器直接复用；不可用时只启动原有 `SafeTGDemoBrowser` 任务，等待就绪，不修改浏览器配置或 API。
- 启动失败有明确提示，说明尚未提交上游订单、未付款。仍需要 Administrator 的交互登录会话。
- CDP 连接和命令有超时，断开时立即拒绝所有未完成请求。验证码等待只容忍页面导航造成的上下文变化，不会吞掉浏览器断线。
- 已开始处理的订单不会自动重启浏览器或重新提交，避免重复创建订单。既有失败队列仍保留，不自动重放。

现有浏览器任务恢复为无运行时长限制，失败重启 3 次、间隔 1 分钟；正常退出由下一笔订单的启动检查处理。完整恢复脚本原本已使用这组设置。原任务 XML 和代码保存在服务器 `data/hotfix-backups/20261117-browser-connection`。

本地 49 项模块测试通过，包括新增 7 项浏览器测试。新增测试覆盖正常复用、启动后等待、启动失败、响应匹配、连接中断、请求超时，以及验证过程对断线和导航错误的区别处理。Windows 线上新增 7 项测试同样通过；实际 CDP 连接成功，首页加载完成、表单及模板列表可用，部署文件校验和一致。没有创建测试订单或执行付款，部署前后运行配置及付款账本哈希一致。

`config/restore-overlays.json` 和生产代码指纹清单已更新，恢复基线快照时包含此次补丁。运行配置、钱包和付款记录不属于本次修改范围。
