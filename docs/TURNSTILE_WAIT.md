# 订单页面验证与确认

## 当前流程（2026-11-26 更新）

程序先在新页面选择模板，填写姓名、地址和邮箱，再点击“创建支付订单”。网站随后启动订单验证并检查资料。等待超过 5 秒时，程序报告进度。只要订单确认窗口打开、确认按钮可用，就立即继续，最长等待 60 秒。

网站返回表单错误时会立即记录原因。60 秒内未出现可确认的窗口，本单在确认创建上游订单前结束。

## 2026-11-16 历史修复记录

故障发生在创建第三方支付订单之前：旧程序只等待约90秒获取 Turnstile 响应，超过时间抛出异常，订单页面直接显示 Node 堆栈。某一单成功不意味着后续每次都能免人工通过第三方验证。

修复内容：

- 每次验证码等待最多5分钟，仍从新文档开始，绝不复用上笔订单的令牌。
- 等待超过5秒后，子进程向处理器报告等待状态，订单页显示“等待人工验证”及服务器 Chrome 操作提示。即使超过页面原来的3分钟陈旧状态阈值，也保留该操作提示。
- 人工在同一页面完成验证后，继续当前订单；填表后再次检查验证状态，失效时等待用户在原页面完成。
- 父进程总时限改为14分钟，覆盖最多两次5分钟等待和页面加载/建单时间。总时限终止不能一概推断外部订单未创建，须核对；单纯验证码等待超时发生在点击创建按钮之前。
- 等待状态回调按顺序执行，终态前等待回调完成，避免迟到的“等待”覆盖失败或付款状态。
- 新失败提示只展示原因，不暴露完整 Node 堆栈。历史失败记录不改写、不自动重放。

没有改变 API、令牌、钱包、付款规则、既有订单数据或验证码安全机制。没有自动点击、破解或代过人机验证。人工步骤仍需在服务器 Chrome 内完成，不能在自己电脑另开浏览器代替。

操作方法：刷新订单页面，必要时重新登录；已有缓存可用 Ctrl+F5 强制刷新。新订单显示等待提示时，在服务器 Chrome 的 addrs.xyz 当前页面完成验证，保持页面不刷新，程序会继续。不要提前在另一页验证、重复提交订单或同时开第二个消费者。

验证：38项机器人模块测试通过（含新增4项等待/回调/错误提示测试）；2项客户端/SSR状态显示测试通过；1项恢复补丁完整性及新快照不覆盖测试通过。Windows现场再次执行新增4项测试通过，部署后健康检查正常。未创建测试支付订单、未发送测试邮件或执行付款。
